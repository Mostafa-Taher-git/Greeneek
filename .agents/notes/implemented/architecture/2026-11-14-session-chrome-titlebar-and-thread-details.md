# Agent Note: Session chrome — the titlebar and the Thread Details panel replace the session header

Status: implemented

## Problem

The conversation column carried a second header bar — breadcrumb title, view menu, action row, utilities — under the window chrome. The owner's T3 reference puts the Session's chrome in exactly two places: the window chrome (brand, session title, the three panel toggles) and the Thread Details column (the Session's own verbs and facts). In Greeneek the duplication was mechanical as well as visual: each of the three header slots had one occupant, the header entry shared a store with the session body, and the per-Session verbs lived in both the header row and the sidebar row.

## Decision

The session header is gone; the conversation column is the titlebar row, the scrollport, and the composer. Session identity lives in the titlebar, Session verbs and facts live in the Thread Details panel, and the slot contract mirrors that split:

- `conversation.session.header`, `.header.actions`, `.header.lineage`, and `.header.utilities` are removed, together with ui-conversation's `ConversationSessionHeader`. The conversation registration owns `conversation.session` alone.
- The details column's contract is `conversation.details.thread` (single, session) — the whole card — with `conversation.details.thread.action` (list; renamed from `conversation.details.actions`), `conversation.details.thread.lineage` (single), and `conversation.details.thread.fleet` (single) as its children.
- The `conversation.details.thread` SlotMap member lives in ui-workspace's contract, because that package owns the card component and its props (`ThreadDetailsPanel`, `ThreadDetailsPanelInjected`). ui-chat's `details` entry declares the hole and renders the card through its `DetailsPanel`; ui-chat keeps a type-only ui-workspace edge to see the member. The reverse edge would close the compile cycle ui-workspace → tool-owned-render → ui-chat.
- ui-sidebar registers the `titlebar` entry that ui-layout's AppFrame renders on every host: the brand, the session title (a button that returns to the Session's Chat view through `ctx.layout.showConversation()` then `ctx.uiConversation.selectView(sessionId, 'chat')`), and the three panel toggles (thread details, terminal drawer, right panel) driving the layout's `SessionPanelControls`. The desktop host marks `documentElement[data-desktop-titlebar]`, reserves inline-end space for the injected window controls, and toggles maximize through the preload bridge on double-click; the web host renders the same row without those desktop affordances.
- ui-workspace's card (`ThreadDetailsPanel`) is a floating card in a transparent details gutter, not a bordered sidebar. It carries the device row (Host hostname from `node:os.hostname()`, with a copy control and transient confirmation), the workspace row with the shared open-in split, branch and change-count rows with no version-control heading, the action row (`conversation.details.thread.action` registrants: agent-preset label, Team, background jobs, Schedule catalog, Trajectory, transcript export), the pin and archive buttons with the overflow menu, the Lineage section, and the Live Fleet section. The lineage and fleet sections follow `HostObservable<boolean>` occupancy hooks over their holes, so each exists exactly while an occupant does.
- The independent right panel becomes a T3-shaped "Open a surface" launcher registered by ui-sidebar into `rightbar`, listing only destinations this app has: Terminal (the activity drawer with its real `mod+j` chip), Trajectory and Chat (the current Session's conversation views), Settings, and Dashboard. Browser/Files/Diff/PR/Device rows are omitted rather than faked. Thread Details and the right panel open independently; both can be open together. ui-wave's Live Fleet moved out of `rightbar` into the card's fleet hole; the FleetSidebar surface and its auto-open behavior are removed.
- The sidebar fully closes: `SIDEBAR_COLLAPSED = 0`, no compact rail, and the column takes the `hidden` attribute. The titlebar carries two leading buttons before the fish brand — sidebar toggle and New Session — so both are reachable in the closed state. ui-sidebar injects `toggleSidebar` and `startSession` into the titlebar; AppFrame passes `sidebarCollapsed` as an owner fact.
- Thread Details is a click popover, not a column: AppFrame gives it no grid track and no drag handle; the toggle opens a fixed 300px wrapper under the titlebar whose 10px padding yields the card's 280px content width, and a pointer outside the card and the titlebar toggles dismisses it. When the right panel is open the popover sits beside it (`data-rightbar-open`), so both are visible at once. The layout still stores a details open/closed preference (`DETAILS_DEFAULT = 300`) under `gnk.layout.panels.v2`, but no width is ever negotiated.
- ui-agent-team's roster board portals to `document.body` with fixed coordinates computed from its trigger. The card clips its own overflow, so an in-card panel lost its background and rows below the card edge; the portaled board renders in full.
- ui-subagent's lineage renderer is `ThreadDetailsLineage` (renamed from `SubagentHeaderLineage`) registering into `.thread.lineage`; ui-workspace owns its owner share `ThreadDetailsLineageOwnerProps { lineageSessionId, displayTitle }`.

## Alternatives considered

- **Keep the header and move only the toggles.** Partial T3 parity would have left three near-empty header slots, the store share, and verbs in two menus; rejected in favor of removing the duplicated surface outright.
- **ui-chat owning the `conversation.details.thread` SlotMap member.** The member would sit beside the hole declaration, but ui-workspace's contract would then need a ui-chat type edge, closing the cycle ui-workspace → tool-owned-render → ui-chat; rejected — the owner of the component owns the member, and ui-chat's existing type-only edge reads it.
- **A dedicated ui-thread-details package.** The card shares ui-workspace's locale namespace, session verbs, open-in machinery, and pin/archive/delete plumbing; a package boundary would either duplicate those or widen ui-workspace's exports for a single consumer; rejected.
- **Faking T3's Browser/Files/Diff/Pull-request rows in the right panel.** Greeneek has no such destinations; every row there must open something real, so the launcher lists only the app's actual views and pages; rejected.
- **Keeping FleetSidebar in the right panel.** The owner's reference puts Lineage, Previous agents, and Live Fleet in the thread card and reserves the right panel for the surface list; the dedicated sidebar, its duplicate lineage tree, and its auto-open-on-running edge are removed in favor of one fleet body in the card; rejected.
- **A resizable details sidebar/column.** The owner requires one fixed card size and a button-driven popover, so a drag handle and a negotiated grid track would contradict the contract; removed.
- **A compact rail for the closed sidebar.** The owner wants the sidebar to disappear completely; the 56px rail with leftover icons is replaced by a zero-width hidden column and titlebar-leading toggle/New Session buttons; rejected.
- **Keeping the Agent Team board inside the card.** The card's overflow clipping cut the board's background and member rows at the card edge; portal with viewport-clamped fixed coordinates keeps the whole board visible; rejected the in-card panel.

## Consequences

- The popover still hosts the tool inspector (`conversation.details.tool`) beneath the thread card; the three keyboard bindings (`mod+shift+b` / `mod+j` / `mod+alt+b`) are unchanged. Only the right panel owns a width preference (default 360); the details preference is open/closed state under `gnk.layout.panels.v2`, and the two can be open together. Concession tests now drive the right panel, since details no longer concedes.
- The device row's hostname travels on the ready frame as `RemoteEventHostInfo.hostname` (Host `node:os.hostname()`), through the gateway into `RemoteHostFacts.hostname`, and reaches the component through the inject `hooks` compartment's `hostInfo` observable. A missing hostname (before ready, or on an older host) hides the device row without affecting the workspace row.
- The session body is the only conversation entry sharing the chat store with the composer; view selection routes through the body's registered selector (`ctx.uiConversation.selectView`), which is what the titlebar's return affordance drives.
- The card's action row and the sidebar row mean the same verbs through one shared implementation (`sharedSessionInjected` in ui-workspace), so a verb never means two things.
- The open-in cluster, pin set, and git facts that [the session-header-utilities note](../feature/2026-11-11-session-header-utilities-and-pinned-sessions.md) placed on the session header now render in this card.
- The removed header controls move, not vanish: `More session actions`, pin, and archive live in the card, which the layout hides (`hidden` on the closed details column), so assembled-output scenarios must open the details panel before driving them. The panel preference persists per browser context and every session switch closes the column, so `openThreadDetails` in `apps/web/tests/support.ts` reads the toggle's pressed state instead of blind-clicking, and card-only lineage interactions go through it (`openLineage` in the subagent scenarios). The one return control is the titlebar's session-title button (`Return to chat: <title>`), which is idempotent on the Chat view, so the shared `showChat` helper clicks it unconditionally.
- The details column inherits the pre-existing `detailsSession` gate (current Session with `blank === false`), so a toggle click on a blank current Session flips the pressed state without widening the column. The client's list blank bit lowers only on a locally accepted prompt, a list upsert, or a reconnect pull; content that materializes purely host-side leaves the bit stale until the next pull, so `agent-team-panel.e2e.ts` reloads after its host-side appends (the route `subagent-interrupt-ui.e2e.ts` already used) before opening the card.
- The restructure's validation surfaced a dispose race that hardens ui-agent-preset's lifecycle contract: the seat's list-change applier runs off the sessions list store, whose microtask-batched publish can flush between cordis teardown checkpoints, and once the applier's scope is unloaded a context property read throws (`cannot get required service ... in inactive context`), which the async applier turns into an unhandled rejection. The package therefore captures its services while the scope is active — the applier's `currentSession` closure reads the captured `sessions` store, and the controllers and roster helpers take the `ctx.remote` face captured at construction — the same shape the session-controller service and the other `sessions.list` subscribers already use.
- The Schedule reminder trigger and the background-job trigger are card actions (`conversation.details.thread.action`), so scenario steps that switch Sessions (`schedule-after.e2e.ts`) reopen the card before waiting for the trigger to be visible.
- Browser-visible conversation-column output changed wholesale, so the assembled-output lane covers the restructure.

## Verification

- `pnpm run typecheck` compiles clean; `pnpm run test:gui` passes 319 files / 4453 tests (1 skipped). The ui-workspace panel spec covers the device row and transient copy confirmation, the branch/change rows, and the Live Fleet section; the ui-sidebar surface spec covers the five launcher rows and their destinations. The ui-layout frame spec asserts the details popover opens without a track or handle and that both panels can be open together; the ui-agent-team spec still covers the portaled roster board.
- The titlebar spec covers the two leading buttons and their callbacks, and the frame spec covers the sidebar closing to a zero-width `hidden` column whose slot stays mounted for state; the concession tests drive the right panel only.
- The ui-theme stylesheet gates cover the new sheets: the details column rebinds the scrollbar pair on the elevated card and the card's hairline divider draws at 0.5px.
- Regenerated artifacts: `slot-catalog.ts` (`pnpm run gen-client-catalog`), `docs/plugin-catalog.md` (`pnpm run gen-plugin-catalog`), `api-catalog.ts` (`pnpm run gen-cordis-api`) for the added `RemoteEventHostInfo.hostname` field, and four `etc/*.api.md` reports (`pnpm run gen-api-reports`). `gen-cordis-inspect-catalog` fails on an unrelated pre-existing `RemoteErrorDetailsMap` face error in `authorization-controller`; that catalog remains stale.
- The Windows `GNK_SNAPSHOT=replay pnpm run test:web` run reports 16 failed files / 28 failed tests. The inspected failures are the documented accepted classes: win32 `tool-bash` composition (`unknown tool "bash"`), Windows absolute paths where goldens expect `{{cwd}}`, `dev:web` boot via `spawn pnpm ENOENT`, and long-scroll/matcher timeouts. No card or surface-launcher regression appeared. The golden evidence for the restructured chrome remains the ubuntu `recore-web-goldens.yml` dispatch (refresh mode, artifact patch committed in `0f2089a7`) and the read-only replay run on CI.
- Live check on the built web app: both titlebar toggles are `aria-pressed=true` at once — the card is a 280px dropdown in a 300px wrapper anchored below the titlebar (no grid track, no border, no resize handle), positioned beside the open 360px "Open a surface" panel. Clicking outside the card and the toggle group dismisses it. The Agent Team board portals to `document.body` as a 420px panel with its full background and all three member rows visible, no longer clipped at the card edge. The branch/change rows are absent because the opened workspace is not a git repository.
- The dispose-race capture (Consequences) validates across the faces it touches: `pnpm run test:gui` is green, the Windows replay lane reports zero `in inactive context` rejections, and the CI `consumers` replay suite passes all 91 files through built-boot with the committed goldens (`dd26a687`).
