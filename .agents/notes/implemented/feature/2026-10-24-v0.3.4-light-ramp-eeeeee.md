# Agent Note: Light appearance anchored at #EEEEEE

Status: implemented

## Problem

The light theme's neutral ramp was a sage/paper tint (`--dsw-static-neutral-bluish-00` = `rgb(253, 254, 250)`) that fed every surface alias, and all four elevation rungs (`bg-base`, `bg-layer-1/2/3`) resolved to that one value. Raised surfaces therefore collapsed flat-on-flat, the light foreground aliases borrowed the tinted surface color as text ink, the composer/card hairlines had been calibrated against a near-white base, and five launch/UI surfaces still painted hard-coded whites, so Electron flashed white before the theme applied. The import-era `-bluish` low steps also carried green casts at steps that now read as UI gray (`bluish-100/150/200/300`, plus the scrollbar statics).

## Decision

The light ramp is a pure, untinted gray ladder anchored at `#EEEEEE`; token names, alias structure and the dark block are unchanged (values release). `-bluish` keeps its historic name — the dark ramp still holds the sage family, and `greeneek-*` keeps the brand greens.

Final light values (`body` block of `packages/client/ui-theme/src/styles/design-platform.css`):

| Step | Value | Role |
|---|---|---|
| `--dsw-static-neutral-bluish-00` | `rgb(238, 238, 238)` | page/base rung |
| `-50` | `rgb(230, 230, 230)` | inset fills, code blocks, sidebar fill |
| `-60` | `rgb(224, 224, 224)` | module cards, selector/tip |
| `-75` | `rgb(218, 218, 218)` | hover fills |
| `-100` | `rgb(210, 210, 210)` | active fills, inline code |
| `-150` | `rgb(200, 200, 200)` | press/ghost-hover |
| `-200` | `rgb(108, 108, 108)` | dimmed label (placeholder and disabled text) — 4.53:1 on `#EEEEEE` |
| `-300` | `rgb(177, 177, 177)` | disabled/edge gray |
| `-400` | `rgb(103, 103, 103)` | `label-caption` — 4.88:1 on `#EEEEEE`, 4.53:1 on `#E6E6E6` |
| `-500` | `rgb(118, 118, 118)` | ghost-active border — 3.91:1 |
| `-600` | `rgb(98, 98, 98)` | `label-tertiary` — 5.26:1 |
| `-700` | `rgb(90, 90, 90)` | `label-secondary` — 5.94:1 |
| `-750` … `-1000` | unchanged | brand green + ink |

`-400` and `-200` sit where the AA 4.5:1 text floor puts them: 4.5:1 against `#EEEEEE` needs `rgb(108, ·)` or darker, so the light text ladder has roughly 20 levels of headroom in total and reads 108 / 103 / 98 / 90 rather than the wider ramp the pre-AA ladder used. `-500` is not a text step — it is the selected-state hairline, which only owes the 3:1 non-text target, so it stays lighter than `-400`. Light `--dsw-alias-state-business-primary` repoints from `greeneek-500` to `greeneek-600` because markdown link text measured 3.92:1 on `#EEEEEE` and 3.45:1 on the `#E0E0E0` module fill; the deeper step is the same brand green.

`--dsw-static-neutral-00` stays white and is now the foreground carrier: `--dsw-alias-label-primary-foreground` / `-inverted` were repointed off `bluish-00` (repoint, not recolor), so the text-on-brand pair no longer rides a surface token. The scrollbar statics `--dsw-static-neutral-200/300` (light block only) were neutralized off the sage family and then darkened to `rgb(132, ·)` / `rgb(112, ·)` so the thumb clears 3:1 against every rung it scrolls over (1.50:1 and 1.85:1 before).

Elevation ladder (light aliases, same names, no new tokens): `bg-base: #EEEEEE`, `bg-layer-1: #F2F2F2`, `bg-layer-2: #F7F7F7`, `bg-layer-3: #FBFBFB`, and `bg-overlay` (the popover/dialog surface, previously the sage `bluish-150`) also `#FBFBFB`. Hairline alphas were re-derived over the new base: `border-l1 0.06`, `border-l2-darkmode-thin 0.14`, `border-l2 0.14`, `border-l3 0.16`, `border-l4 0.20`. The composer card keeps its ink hairline (`color-mix(… label-primary 12% …)`) and its flat stroke+shadow elevation, so nothing needed re-coloring there.

Hard-coded near-whites that painted app surfaces were replaced: `gradient-shadow-text.css` think/think-select gradient stops now read `var(--dsw-alias-bg-base)`; `web/src/base.css` fallback is `#eeeeee`; `ModelSelect.module.css` slider knob is `var(--dsw-static-neutral-00)`; Electron `window-options.js` background and `startup.html` startup background are `#eeeeee`; `web/src/boot-page.module.css` boot surface, secondary/tertiary labels and border alpha follow the same ladder (that file is the first paint, so leaving `#fdfefa` there would have preserved the launch flash). Whites that paint *foreground* on brand/dark fills (`InputBar` send arrow, `HoverCard` copied label, `Rows` hover title, titlebar chrome, landing selection) were audited and deliberately left alone.

Test pins updated: `ui-layout/tests/theme-presenter.client.spec.ts` (light fixture now `rgb(238, 238, 238)`), `apps/web/tests/seeded-history.e2e.ts` context disclosure (`rgb(230, 230, 230)` fill, `rgb(98, 98, 98)` tertiary text), `apps/desktop/test/desktop.test.js` (`#eeeeee`). Those two seeded values were already stale from the importer (they never matched the shipped palette); the pins now match what the CSS resolves to.

## Alternatives considered

**Tinted family (`#EDEFEC` around `#EEEEEE`).** Rejected by the owner in the v0.3.4 decision sheet: the light appearance reads as neutral gray, brand identity stays in `greeneek-*` accents.

**Keep `--dsw-alias-bg-base: var(--dsw-static-neutral-bluish-00)` instead of a literal.** Rejected: the ladder needs three *lighter* rungs than the base and the ramp only descends below `#EEEEEE`; literals on the four bg aliases keep the ladder explicit without inventing steps above `-00`.

**Ship the suggested text values (`400: 117`, `500: 115`, `600: 122`, `700: 90`).** Rejected: `600: 122` measures 3.70:1 on `#EEEEEE` and fails the tertiary 4.5:1 contract, and 122 is lighter than 117/115, which breaks the step order.

**Use the `bluish-00` step for the floating/elevated button fills as the brightest control surface.** Rejected: those buttons (chat scroll-to-bottom, panel drag handle, inline rename input) are flat stroke+shadow controls by design; letting them resolve to `#EEEEEE` keeps them flush with the base and the elevated hairline carries the edge. Repointing them to white would reintroduce a near-white control surface the release is removing.

**Leave the scrollbar statics tinted.** Rejected: `rgb(196, 204, 191)` / `rgb(164, 173, 160)` are visibly green against a pure gray base and they feed only the light scrollbar aliases.

## Consequences

- Every light surface rung is distinct (`#EEEEEE → #F2F2F2 → #F7F7F7 → #FBFBFB`, each step ~1.04–1.12:1 separation) and the base reads `#EEEEEE` end-to-end: page, boot page, Electron launch background, composer, dialogs, popovers.
- Text on the base: primary (ink) 10.15:1, secondary 5.94:1, tertiary 5.26:1, caption 4.88:1, placeholder/disabled 4.53:1, link 5.19:1, ghost hairline 3.91:1. On the darkest inset fill (`#E0E0E0`): secondary 5.22:1, tertiary 4.62:1, link 4.56:1. On the `#E6E6E6` code-block banner: caption 4.53:1.
- The caption and dimmed steps ship darker than the first v0.3.4 ladder, and `verify-theme-contrast` is what moved them: the shipped CSS had `label-caption` at 3.40:1 and `label-dimmed` — the `::placeholder` and `:disabled` colour — at 1.50:1 on `#EEEEEE`.
- The dark block is byte-identical (both `body[data-ds-dark-theme]` blocks compared against `HEAD`), so dark-mode users see no change.
- The ramp is still named `-bluish` while holding gray light values; that mismatch is intentional and documented at the top of `design-platform.css` so a future tint change stays a values edit.
- Launch-time white flash is gone from all three first-paint paths (Electron window background, startup HTML, boot page).
