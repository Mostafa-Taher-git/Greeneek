# Agent Note: Dashboard owner corrections and Arabic rewrite pass

Status: implemented

## Problem

The owner ruled the shipped Dashboard and Arabic dictionaries wrong (S5-01, S5-03), so this slice closes S5-01a/b/c/d, S5-03a, and the S8-20 chart foundation without inventing any number: every new figure is folded from projections the client already holds, and anything without a projection is shown as unknown with its reason.

## Decision

- **Full page (S5-01a).** The `dashboard` destination (`sidebar.primary.action` seat under New Session, `shell.overlay` full page, close/Escape/focus-entry, light/dark/RTL) is registered; this slice finishes the New Session page-yield (`open`/`startSession` call `layout.showConversation()` first) and adds the missing `open(sessionId)` drill-through face, so detail-table rows drill into permitted session details.
- **Metrics (S5-01b).** `dashboard-model` sums latency from `sessionStats` (`llmMs`, `toolMs`, `ttftMs`/`ttftSteps`, `decodeMs`) and mirrors one request per closed step; the page adds Requests, Cache-write tokens, and Latency cards plus an Operational-health section (data state, pricing state, plan state, outcome state, recovery) and a source note that CLI source is the provider and the Maestro lane is the `maestro` preset row. Reasoning tokens stay inside Output with an explicit note because provider accounting does not split them. Success/failure/cancel **cannot** be shown honestly: `step/end` carries no outcome and no projection aggregates turn outcomes, so the page states `dashboard.outcomesUnknown` instead of fabricating counts. API-key plan labels likewise have no non-secret reference anywhere in the client, so the page states `dashboard.planUnknown` and never shows key material.
- **Cost honesty (S5-01c).** One versioned catalog (`dashboard-pricing.ts`) holds cost truth, unknown-with-reason (`no-catalog-entry`/`no-recorded-usage`/`mixed-currency`) covers every unpriced amount, historical costs never use current prices, and catalog version travels with every amount.
- **States and accessibility (S5-01d).** Loading (`list.phase`), recoverable error (`workspaces.state === 'error'`), partial (`dashboard.partial`), empty, pricing-unknown, plan/outcome-unknown, and permission/analytics-off keys all render as text. The fold is memoized (`useMemo`) and bounded by `DASHBOARD_AGGREGATION_BUDGET_MS` (50 ms) over one linear pass; a 2000-row fold test guards the budget. Status is never color-only (health rows carry text states; `StateDot` remains `aria-hidden` beside text).
- **Charts (S8-20).** New `ChartContainer`/`ChartTooltipContent`/`ChartLegendContent` in `ui-primitives` ports the shadcn/ui Chart contract (a `chartConfig` mapping series ids to `--chart-*` custom properties, tooltip/legend content renderers taking complete label props) onto the token/CSS-module layer, and the Dashboard breakdowns (models/providers/presets) render through it. Every chart ships its own data `<table>` so the visual and the accessible alternative cannot drift.
- **Arabic (S5-03a).** Every `ar` value in all 29 client dictionaries (plus `ui-chat/locale.ts`) was audited; keys are unchanged, so the typed `satisfies Record<XxxKey, string>` parity contract holds throughout. Rewrites fix correctness, naturalness, and terminology rather than re-translating good strings: token terminology is standardized on توكن (was رموز in `ui-workspace`, `ui-agent-team`, `ui-settings-models`, `ui-trajectory`); turn terminology is standardized on دور (was جولة in `ui-chat`); `headerHint`/`trigger`/`suggestions`/`member.open`/`fleet.preset` Latin or wrong-word fixes (`shell`→أوامر الطرفية, `markdown`→ماركداون, `surface`→حدث, `Preset`→إعداد مسبق); `ui-reference` day/month/year abbreviations are replaced with full words; `ui-model-selection` catalog wording and model-name agreement are fixed. Brand, product, and model names stay verbatim (Greeneek, Craft, Melody/Harmony, Maestro, PX, `Skill`, `tok` units) — matching the dictionaries' existing notes. RTL/bidi/logical-CSS parity stands on the existing structural work: `verify-logical-css` passes, and every new Dashboard row uses `dir`/`bdi` isolation for routes, paths, and model ids.

## Alternatives considered

**Introduce Recharts and Tailwind for charts.** Rejected: the client has no Tailwind (only `apps/landing`), and adding a chart library for three ranked lists is a larger architectural change than the charts themselves, exactly the tradeoff the S8-20 measurement note flags for an owner decision; the shadcn contract port onto the token/CSS-module layer stands alone.

**Adopt PandaCode precedents wholesale (Tauri desktop, Rust/SQLite, plain TypeScript, no bundled Chromium/Node/React).** Rejected in part: adopted are local-first honesty (no telemetry, no fabricated spend), per-turn elapsed precedent for the latency card, and plan labels only from non-secret metadata; rejected are procedural-scene theming and the desktop-bridge Craft surface (different product shape; Craft stays a gateway, not a Dashboard dependency).

**Adopt T3 Code precedents wholesale ("agent harness control surface", mobile + web + desktop, subscriptions on existing CLIs).** Rejected in part: adopted are the control-surface framing (Dashboard as a destination, not an admin template) and subscription-style usage accounting; rejected are remote/mobile companions and subscription APIs (Greeneek is local-first; no remote call can price usage without making spend a promise the catalog does not back).

**Copy a spend-analytics chart library pattern from either reference.** Rejected: both references instrument usage locally and never invent prices, which is the same honesty rule `dashboard-pricing.ts` already enforces; neither offers a spend-analytics chart library pattern worth copying.

## Consequences

The Dashboard reads as an honest control surface: every figure traces to a held projection, every unpriced or unknowable figure names its unknown state instead of fabricating a count, and every chart carries its own accessible table so the visual and the text cannot drift. The Arabic dictionaries keep their keys and parity contracts while fixing token/turn terminology, Latin or wrong-word leaks, abbreviations, and catalog agreement, with brand names verbatim and RTL parity preserved through existing structural work and `dir`/`bdi` isolation. The cost is the S8-20 library decision itself: Greeneek owns the chart contract port and the 50 ms aggregation budget rather than depending on a chart library, and outcome/plan states remain explicitly unknown until a projection aggregates turn outcomes or a non-secret plan reference exists. Verification pins the shipped state: `npx tsc -b` on `ui-primitives`, `ui-workspace`, and every locale-touched client package is clean; `npx vitest run` on `ui-workspace` + `ui-primitives/chart` + `locale` reports 258 tests pass and on all 27 locale-touched client packages reports 1927 tests pass; `pnpm run verify-client-ui-i18n` reports 533 files locale-owned (caught and fixed one hardcoded unit, `dashboard.durationUnit`); `pnpm run verify-logical-css` reports no unadmitted directional physical geometry; no web golden or session snapshot needed re-recording because no scenario opens the Dashboard and no scenario runs Arabic.
