## Problem

`desktop-v0.3.6` is the current public release and has 14 assets, but the installed Windows build cannot start: the packaged app fails while loading `@greeneek/gnk-session-telemetry-otel` because `@opentelemetry/otlp-transformer` is missing from the deployed module tree. A release that passed CI and uploaded complete-looking assets still produced an unusable application. That is the highest-severity fact in this plan.

The release program is also incomplete in three independent ways.

First, the eight failed-check clusters still contain live defects or live recurrence hazards: the desktop release workflow has a broken `workflow_dispatch` path and Windows Bash steps; PRs #87, #88, #89, and #90 are open; the pi-ai upgrade is not adapted; Dependabot does not group lockstep families; generated catalogs are not guarded locally; workflow files duplicate the pnpm pin and retain Node-20-targeted actions; three session-snapshot pollers still mask timeout diagnostics; local hooks do not match CI hygiene gates; and Vercel builds unrelated changes while landing has no repository CI build.

Second, the accepted v0.3.4-v0.3.6 product promises were not all delivered. PTC history migration, Craft provenance and real app smoke, Pixels Designer and Instructor flagship flows with evaluations, the Army Fleet tail, Maestro G1 worktree integration and merge governance, Maestro G2 fleet settings and favorites, Arabic logical-CSS/RTL completion, the Dashboard, and the final live end-to-end sweep remain partial or absent. Some ledger rows are stale in the opposite direction: honest `lastTool` and 12.5 Hz Fleet coalescing are already implemented and must not be rebuilt.

Third, historical check debt is large: the supplied audit accounts for 221 failed and 7 cancelled GitHub Actions runs plus 10 failed Vercel statuses. Historical runs cannot be made green retroactively. The release must instead prove that every live defect has a root-cause fix, every open red check is resolved, every recurrence has a regression guard, and the v0.3.7 commit and artifacts are green under stronger gates than v0.3.6 used.

The owner's goal is explicit: v0.3.7 must contain everything that is still owed, be fixed in the best way rather than patched cosmetically, and be usable daily without hidden startup failures, broken modes, misleading analytics, unsafe orchestration, or untriaged CI failures.

## Proposal

### 1. Release thesis and scope contract

v0.3.7 is the **completion release** for the v0.3.4-v0.3.6 program. It is not a new feature wave and it is not a cosmetic version bump. It closes the public startup regression, all eight failed-check clusters, and every accepted product commitment that the prior tags did not finish.

The release has four non-negotiable outcomes:

1. A clean install of the exact v0.3.7 Windows and Linux artifacts launches, reaches the web service readiness line, serves the authenticated UI, and survives restart without a missing-module error.
2. Every open pull request is merged with green checks or closed with a written technical reason; `main` is green; the v0.3.7 release commit has no failed required check; no new Vercel failure is posted for unrelated changes.
3. The accepted v0.3.4-v0.3.6 product obligations are implemented and evidenced, or explicitly returned to the owner as a scope decision before implementation. No item may remain silently partial.
4. The final evidence set is reproducible from the exact pushed SHA and the exact downloaded artifacts. A green source test alone cannot satisfy an artifact, live-app, RTL, or Dashboard claim.

**In scope for v0.3.7**

- The packaged-runtime startup crash and the staging/closure defect that allowed it.
- Release workflow correctness, dry-run support, installed-artifact smoke, artifact integrity, and release communications.
- All eight supplied failed-check remediation clusters.
- PTC retirement/migration resolution without breaking recorded sessions.
- Craft provenance, real Windows app smoke, Pixels Designer and Instructor flagship flows and evaluations.
- Army Fleet completion.
- Maestro G1 completion and the owner-requested G2 fleet settings/favorites path.
- Arabic RTL/logical-CSS completion and review.
- Dashboard and its trustworthy local usage/pricing provenance model.
- Full product inventory, hardening, live-safe end-to-end verification, and release evidence.
- Documentation, issue/PR hygiene, branch protection, and supply-chain improvements needed to keep the release durable.

**Explicitly out of scope**

- The parked upstream re-platform program in #63-#85, including the Node 24.9/pnpm 11.28.5 platform floor (#64), pi-ai 1.3 route split (#70), wholesale web-client re-platform (#71), upstream desktop re-platform (#72), complete CI parity (#79), the 78-gate adoption program (#83), and Python SDK parity (#85). - A claim of complete support for all 13 ArtCraft applications. v0.3.7 must catalogue all 13 honestly, verify every app actually installed on the test host, and claim production support only where a real artifact-producing smoke exists.
- Unauthenticated ArtCraft attach, screen scraping, synthetic GUI input, or silent installation.
- Invented pricing, invented API-key plan metadata, or presenting mock output as live evidence.
- Moving or deleting an existing `desktop-*` tag. A tag is immutable user history.
- Deleting personal files or untracked owner material to make the worktree look clean.

### 1b. Owner-requested UI/UX addendum

These requirements are part of v0.3.7 and ship in the same candidate as the runtime and release fixes.

- **Kimi-inspired, not Kimi-copied.** Use Kimi's calm hierarchy and approachable density as interaction reference while retaining Greeneek's brand, themes, locales, plugin slots, and accessibility.
- **Small bots.** Preset/bot cards use a compact avatar, tighter spacing, a two-line description, clear default/selected treatment, and accessible management actions. Built-in/custom grouping and every existing action remain.
- **Understandable modes.** Mode choices show a glyph and persistent label at practical widths, keep keyboard radio semantics, expose the active mode clearly, and never depend on hover to reveal essential copy.
- **Composer hierarchy.** One calm elevated composer, integrated mode/model controls, clear Send/Stop states, and no overlap with Emergency Stop or running controls at supported widths.
- **Settings is a page.** Clicking Settings opens a full-height destination in the main content column, never a modal, popover, or small native window. The conversation stays mounted so drafts, scroll, and active-session state survive. Back, close, Escape, section navigation, onboarding deep links, focus entry, light/dark themes, and RTL remain functional.
- **Evidence.** Component tests cover the page transition and preserved conversation; browser replay covers open, section switch, close, and accessibility roles; owner confirms the dev build before any tag.

- Work directly on `main`; do not create another implementation branch. A separate release-candidate tag, when approved, is immutable.
- Delete a branch only after its unique commits are merged, archived by a reachable tag, or explicitly accepted as disposable. Never delete `main` or an existing `desktop-*` tag.
- Do not delete anything outside the Greeneek folder unless it is demonstrably Greeneek-owned or was created for this task's tests. Never run broad personal-directory cleanup.
- Never commit credentials. Live lanes self-skip without `GREENEEK_API_KEY`.
- After each milestone, update the **Execution ledger** at the end of this file with the exact commit, changed files, commands, results, running processes, blockers, and next action. A successor must be able to resume from that section alone.
- Open the desktop in dev mode for owner confirmation before creating `desktop-v0.3.7`. Do not tag while the dev candidate is unconfirmed.

**Meaning of "everything is done"**

A requirement is done only when all five are true: the implementation exists in the shipping path; focused tests cover the behavior and its failure modes; the relevant repository gate passes on the exact commit; the user-visible or artifact-level evidence exists where the claim is user-visible; and the ledger row names the command, result, artifact hash, or file that proves it. A code path with no real-composition test is not done. A mock presented as live is not done. A skipped test counted as green is not done.

#### P0-A. Packaged runtime integrity and the v0.3.6 startup crash

**Status: DONE-VERIFIED.** Staging cleans before every run (`rmSync`), dereferences escaping links, materializes workspace and external closures, and `after-pack.cjs` fails the pack on an escaping or absolute link. `smoke-installed.mjs` probes the OTel graph; the release workflow runs `smoke:installed` on both platforms and `publish` needs them. Item 12 is done: the runbook records the startup symptom, the missing-edge root cause, and the support log path, and the v0.3.6 release notes carry the known-issue warning.

**Objective:** make the deployed module tree provably self-contained and prevent any future release from publishing an artifact that only works on the build machine.

**Evidence and root cause:** `packages/session/session-telemetry-otel` correctly declares `@opentelemetry/exporter-logs-otlp-http`; that exporter declares `@opentelemetry/otlp-transformer`; the lockfile contains the edge. The staged tree can still resolve the transformer through a symlink that escapes into the build checkout. `apps/desktop/scripts/stage.mjs` preserves pnpm links in `copyPrunedModules()` and `copySymlink()`, while `resolvesInStaging()` uses `existsSync()` and therefore follows an escaping link. `materializeExternalClosure()` skips a dependency that "resolves" only because the build machine still has the source tree. `apps/desktop/config/after-pack.cjs` then copies that tree verbatim. The packaged app loses the link target. This is a staging/closure defect, not a missing upstream package and not a Node version failure.

**Required changes**

- [x] Add a failing regression fixture before changing the copier: a synthetic pnpm-style tree where package A requires package B, A's `node_modules/B` is a symlink outside the staging root, and the staged result must still contain a real B at the correct importer resolution location. Add a second fixture with two incompatible versions of B to prove nested resolution is preserved.
- [x] Refactor the staging closure into testable functions. Export only what tests need; do not widen the production API.
- [x] Clean `.staging/app` before every stage. A stale staged tree must never satisfy a new build.
- [x] Replace `resolvesInStaging()` with a self-contained resolver that accepts only real package directories whose `realpath` stays inside staging. A symlink that points back into staging may be canonicalized only when it cannot escape; an external target is always materialized.
- [x] Change symlink copying so runtime links never preserve an absolute path into the checkout. Dereference the package directory and copy its real files. Preserve nested version conflicts under the importer rather than flattening them to one top-level copy.
- [x] Materialize the complete production graph from the importer's perspective, not from a single top-level `node_modules`. Use the lockfile and Node resolution data as evidence; do not add every transitive package to the desktop manifest.
- [x] After the closure pass, assert every required production dependency edge resolves inside staging, including peer dependencies that are installed. Fail on an escaping link, a dangling link, a missing package, a missing declared `main`, or a version that does not satisfy the importer's range. Optional platform-only dependencies may skip only with a recorded reason.
- [x] Make `after-pack.cjs` verify the copied tree has no escaping or absolute links and fail the package if it does.
- [x] Add a targeted runtime import check: from the staged telemetry package context, import the telemetry entry and the exporter, then assert `@opentelemetry/otlp-transformer` loads. Also probe the next likely OTel packages (`sdk-metrics`, `sdk-trace`, `core`, `resources`, `sdk-logs`, `api-logs`) so the test catches the next missing edge instead of stopping at the first.
- [x] Add `apps/desktop/scripts/smoke-installed.mjs`. It must install or extract the actual generated artifact into a temporary directory outside the repository, clear `NODE_PATH` and `NODE_OPTIONS`, run the bundled Node against the installed `resources/app` tree, boot the real `web` profile, assert the readiness line and auth fence, then launch the actual Electron executable in a smoke mode that exits non-zero on boot failure. The smoke mode must be internal, documented, and must not change normal user startup.
- [x] Run `pnpm --filter @greeneek/desktop test`, `smoke:packaged`, and `smoke:installed` on both release runners before artifact upload. The publish job must depend on both platform smokes.
- [x] Add the startup error text and support-bundle path to the release runbook. Update the v0.3.6 release notes with a known-issue warning and a link to v0.3.7 once published. Never move the v0.3.6 tag.

**Tests and evidence**

- Unit: escaping symlink, nested version conflict, missing transitive package, optional platform skip, dangling link, absolute-link rejection, deterministic staging from a dirty previous stage.
- Integration: copy staged output outside the repository and run the existing readiness/auth smoke; import telemetry and the OTel graph; assert no escaping symlink remains.
- Artifact: install the exact NSIS output on Windows and the exact DEB/AppImage on Linux; launch the real app; assert no `gnk entry failed to load`; restart twice; assert no orphan process.
- Release evidence: both platform smoke logs, artifact SHA-256, installer filenames, and the exact commit.

**Exit criteria:** the regression fixture fails on the old copier and passes on the new one; both installed artifacts launch from an isolated directory; the release workflow cannot publish without these smokes.

**Do not do:** add `@opentelemetry/otlp-transformer` as a direct telemetry dependency as the primary fix. That hides one edge and leaves the same class of failure everywhere else.

## Alternatives considered

**Treat the startup crash as a one-line dependency fix.** Rejected: adding `@opentelemetry/otlp-transformer` to the telemetry manifest would make this one import pass while leaving every other transitive edge vulnerable to the same escaping-link bug. The staging closure is the defect.

**Rewrite staging to `pnpm deploy --prod` immediately.** Rejected for v0.3.7: the current custom stager exists to avoid TTY/install blockers and to handle native binaries and bundled Node/pnpm. A wholesale rewrite adds release risk while the product is broken. The plan repairs the closure and adds a lockfile/Node-resolution invariant; a deploy-based simplification can be evaluated after v0.3.7 with differential artifact tests.

**Backfill v0.3.4 and v0.3.5 releases.** Rejected: those trees predate the fixed pipeline and the startup fix. Publishing them would add old, unverified installers and confuse update channels. Document them as skipped pre-v0.3.6 tags.

**Ignore the pi-ai update until #70.** Rejected: it leaves an open red PR and postpones the same contract work. Adapt 0.87.1 now, then move to 1.3 under the parked route-split program.

**Add full lint to pre-commit.** Rejected: it would make every commit slow and encourage bypass. Full lint belongs in pre-push; staged lint stays in pre-commit.

**Auto-regenerate catalogs in a pre-commit hook.** Rejected: input globs are incomplete, generation is expensive, and parallel jobs race build outputs. A pre-push freshness check with an actionable error is safer.

**Use Vercel's inline `git diff` ignore command.** Rejected: path semantics depend on the project root and miss lockfile importer changes. A tested helper is more reliable.

**Delete the PTC preset immediately.** Rejected unless a real census proves no recorded sessions. Silent substitution on explicit resume is a data-integrity failure. Branch B preserves history while removing the creation surface.

**Claim all 13 ArtCraft apps are supported.** Rejected: only installed and observed apps can be verified. The release will publish an evidence matrix and honest capability states.

**Build the Dashboard from telemetry records.** Rejected: the telemetry seam carries full event bodies and is outbound-oriented. Aggregate locally from `sessionQuery` and `sessionStats`, and expose only non-secret summaries.

**Show estimated costs as zero when pricing is missing.** Rejected: misleading. Unknown is the correct state until a versioned source exists.

**Close flaky tests by retrying.** Rejected: a retry hides a race. Classify, fix, or quarantine with an owner and expiry.

**Ship a single giant release PR.** Rejected: it makes review, bisection, rollback, and evidence attribution impossible. Use the PR map.
