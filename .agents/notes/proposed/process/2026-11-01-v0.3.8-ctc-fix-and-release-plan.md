# Agent Note: Greeneek v0.3.8 fix, CTC conversion, and release plan

Status: proposed

- **Author:** Qoder
- **Date:** 2026-11-01
- **Target release:** `desktop-v0.3.8`
- **Baseline:** `main @ c2dc5a70`; `desktop-v0.3.7` is published (14 assets, checksummed, both platforms booted).
- **Supersedes:** [the v0.3.7 completion plan](./2026-10-27-v0.3.7-completion-and-release-plan.md), whose Execution ledger stays as the historical evidence record. This file is the active to-do list; every box below is deliberately empty.
- **Owner decisions recorded on 2026-11-01:** (1) the code-tools opt-in is renamed **CTC** and must be reversible, (2) CTC carries the useful PTC tool set, (3) the PTC preset is **deleted** — this is the approval that plan P2-01 Branch A required, (4) v0.3.8 is the vehicle.

## Problem

`desktop-v0.3.7` shipped, but three things are wrong with it and one product decision is new.

The lazy code-tools opt-in is misnamed and one-way. Its label ("Code tools") describes nothing about the mechanism, and the host treats the declaration as turn-1-final: `ToolRuntime.presentAs` throws `ToolPresentationLockedError` when a scope re-declares, so a user who enables it cannot change their mind without opening a new session. The owner wants a named, reversible control.

The PTC preset is a dead surface. It carries `retired: true`, is hidden from every creation surface, and duplicates a capability that now exists as a per-session opt-in — but it still owns a composition, tests, goldens, bundle rows, and documentation that keep the retirement from being real cleanup.

CI is red on `main`. The `consumers` job's `Expected-output processes` step fails while the same command passed in a per-lane probe, and that difference is undiagnosed. A release cannot be cut over it, and the release gate now requires this job green.

Everything the v0.3.7 plan left blocked by owner resources stays blocked here until those resources exist; this plan names them rather than silently dropping them.

## Proposal

**Reading the checkboxes.** A box is checked only when the implementation is in the shipping path, focused tests cover it and its failures, the relevant repository gate passes on the exact commit, user-visible evidence exists where the claim is user-visible, and the ledger row names the command or artifact that proves it.

### CTC-02. Make the presentation reversible

- [x] Decide and record the model: the session declares a presentation the user may change, or it stays locked. **Qoder:** the user owns exactly one declaration — the one the Session Controller made on the live agent's own scope — and may unwind it; every declaration the Controller does not own, a preset composition's standing `presentAs` above all, stays turn-1-final. The decision and its rejected alternatives are [the reversible-presentation Agent Note](../../implemented/feature/2026-11-01-ctc-reversible-presentation.md), which cross-links the 2026-08-05 note it narrows.
- [x] Let the user's own opt-in dispose its declaration and re-declare: keep the exact disposer `presentAs` already returns in `packages/api/session-controller/src/commands.ts`, and make the toggle path go through dispose-then-declare instead of a second `presentAs` on the same live layer. **Qoder:** `presentation.ts` holds a `WeakMap` from the agent's own context to that disposer (`rememberPresentation` / `releasePresentation` / `holdsPresentation`); the resumed-agent path in `agent.ts` registers its re-declaration, so a re-adopted Session is withdrawable like a fresh one.
- [x] Accept a desired state on the remote (`enabled`, or an explicit mode) instead of an idempotent "turn it on", and return the presentation now active. **Qoder:** `SessionPresentCodeToolsRequest.enabled` (absent means `true`) and `SessionPresentCodeToolsValue.presentAs: 'both' | 'native'`; a repeat of the state already in force returns it without a second event.
- [x] Append one `tool/presentation` session event **per change** so every model request in the log is reconstructable from the recorded events, and extend the projection that replays it to apply declarations in order rather than keeping the first. **Qoder:** the existing `tool/present-as` event carries `to` and is appended once per accepted toggle, in both directions; its fold already returns the latest event's value, so no projection change was needed — `session-present-code-tools.host.spec.ts` asserts the three-event sequence `both, native, both` and the matching projected value.
- [x] Make the mid-session change safe at the request boundary: the tool list a turn sees must come from the same watermark as the prompt, never from a later toggle. **Qoder:** withdrawal requires an idle Agent — switching a scope to `native` removes `run_code` from its dispatch table, which would refuse a call the running turn was already offered — and the refusal is the typed `tool/presentation-busy`. Enabling stays available at any time because an added presentation cannot strand a planned call; it applies to the next request. Deferring a withdrawal to the request boundary, the way `selectForNextRequest` defers a model, is recorded as the rejected alternative in the Agent Note.
- [x] Update the TypeScript SDK and the Python SDK expected outputs in the same change; neither is covered by `pnpm run test`. **Qoder:** neither projects this surface — `git grep presentCodeTools` across `python/`, `snapshots/`, and `packages/sdk` returns nothing, and the only documentation mention is the unchanged `@Remote('presentCodeTools')` signature line in `docs/subsystems/session.md`. The generated API and persistence catalogs were re-run and `verify-generated-artifacts` reports all 6 current.
- [x] Replace the "locked" refusal copy with the accurate one, and keep the lock as a typed refusal only for declarations that are not the user's own. **Qoder:** `.locked` now reads "The CTC presentation is locked for this session and cannot change." in each locale and is reachable only from a composition-declared scope; a mid-turn withdrawal gets its own `.busy` copy, and a missing runtime keeps `.runtimeRequired`.
- [ ] Tests: enable → disable → enable in one session; the tool set and system-prompt sections follow each state; a preset's composition-time declaration still refuses a user re-declare; cancellation mid-toggle leaves the previous state; a replayed session reproduces every state. **Qoder:** done in `session-present-code-tools.host.spec.ts` are the cycle with one event per change, the idempotent repeat, the never-declared withdrawal, the mid-turn refusal with the declaration left in place, both undo paths when the log write fails, the composition-lock refusal, the missing-runtime refusal, and the silent re-declaration on re-adopt. Still open: a registry-level assertion that each state carries the `run_code` schema and the SDK prompt section (they are asserted today against `presentAs` in `packages/core/tools`, not against a toggled session), and a recorded-session replay of a toggling session, which needs the `tool/present-as` pair added to a snapshot fixture.

## Alternatives considered

**Keep PTC as a retired preset.** Rejected by the owner. The retirement leaves a composition, tests, and goldens that keep the surface alive.

**Rename the label only and leave the lock.** Rejected: a one-way switch is exactly the complaint, and a label change without the toggle leaves the product promise half-kept.

**Let `presentAs` overwrite a scope's mode.** Rejected: that would let a preset's composition-time declaration be replaced by a late user call and fork what the model sees mid-session; reversibility must run through the disposer.

**Delete the PTC preset before the census.** Rejected: a recorded session must not be stranded by an unverified assumption about the owner's log directory.

**Ship CTC without re-recording goldens.** Rejected: the label and the per-change presentation event both appear in committed expected output, and stale goldens are the failure class this repository already hit twice.

## Acceptance criteria

1. The control reads CTC everywhere a user can see it, and enabling then disabling then enabling again works inside one session.
2. Every model request in a toggling session is reconstructable from the session log, and both SDKs' expected outputs match.
3. A preset's composition-time declaration is still immune to a later user re-declare.
4. CTC's tool set equals the useful PTC set, enforced by a composition test rather than stated in prose.
5. No `ptc` preset remains in the repository, and the census that permitted its removal is recorded.
6. `main` is fully green, including all four CI jobs, on the tagged SHA.
7. `desktop-v0.3.8` carries both platforms, updater metadata, checksums, a manifest, and notes that describe the CTC rename and the PTC removal honestly.
8. Every blocked lane is named as blocked; nothing is claimed from a mock.

## Risks

| Risk | Control |
|---|---|
| Making the presentation reversible breaks replay determinism | Per-change session event plus ordered replay, and a toggle test that replays the recorded session |
| Deleting PTC strands a session nobody found in the census | Re-run the census at deletion time and record it; a stored session naming a missing preset must fail loudly |
| The rename churns many web goldens | Touch only goldens whose text moves; review every diff |
| Label and protocol changes land together and hide a regression | Two commits: protocol first, copy second |
| Expected-output diagnosis turns into env-shopping | The job's environment is pinned by a workflow policy test either way |
