## Reading the checkboxes (contract for the executing model)

A box is checked **only** when all five are true:

1. The implementation exists in the shipping path.
2. Focused tests cover the behavior and its failure modes.
3. The relevant repository gate passes on the exact commit.
4. User-visible or artifact-level evidence exists where the claim is user-visible.
5. The Execution ledger (end of this file) names the command, result, artifact hash, or file that proves it.

A mock presented as live is not done. A skipped test counted as green is not done. A box whose proof is blocked gets a `BLOCKED:` note naming the missing input — never a tick. Every item carries an ID (`S1-03` style) so the ledger can reference it without quoting prose.

## Execution protocol for the implementing AI model

1. Read first: root `AGENTS.md`, `packages/AGENTS.md`, `packages/client/AGENTS.md`, `docs/AGENTS.md`, `docs/architecture.md`, `docs/testing.md`, and the owning package READMEs. Verify every path and command in this plan against the tree before editing — source wins for facts, this plan wins for scope; record any conflict and ask before dropping a requirement.
2. Work directly on `main` in PR-sized vertical slices; never start a new slice while the current slice's focused tests are red. Never a giant mixed release branch.
3. Reproduce each defect before fixing it; record the failing command, error text, commit, and environment. Write the regression test first where practical — it must fail on the old behavior and pass on the new.
4. Never weaken a test, add a blind retry, raise a timeout without a diagnosed cause, or delete a failing assertion to green a gate.
5. Generated artifacts, source changes, tests, docs, and this ledger update land in the same commit when they form one contract.
6. After every wave: scoped `vitest --coverage`, `verify-client-domain-graph`, `verify-client-ui-i18n`, `verify-cordis-config`, `verify-generated-artifacts` as applicable, then append to the Execution ledger below with exact commit, changed files, commands, results, blockers, and next action. A successor must be able to resume from the ledger alone.
7. Tick a box only per the checkbox contract; when blocked, annotate `BLOCKED: <missing input>` inline and move on — do not stall the program.
8. Never commit credentials, `.env`, personal paths, or untracked owner material (`.analysis/`, `.kimi-work/`, `working files/`). Live lanes self-skip without `GREENEEK_API_KEY`.
9. Keep tags immutable. Delete a branch only after its unique commits are merged, tagged, or explicitly accepted as disposable.
10. Stop and ask the owner when an OWN-* decision is unresolved and blocks the slice, when a real app/key is unavailable, or when a security boundary cannot be enforced in the operation that makes the decision.
