## Alternatives considered

### Why not copy T3 wholesale?

T3's right panel hosts surfaces (browser, device, terminal, files, diff, PR, side-chat) wired to its WebSocket RPC, PTY layer, and browser runtime. Greeneek does not have host capabilities for those surfaces at this release; copying the names would ship dead controls. Greeneek ships the T3 **visual language and hierarchy** — section headings, 32px rows, 8px radii, chevrons, hairline dividers — with the surfaces it actually has: Lineage, Previous agents, Live Fleet.

### Why not re-record the goldens on this Windows host?

The web replay fixtures were recorded against `bash`; this host composes `pwsh`, so the lane cannot regenerate them faithfully. Hand-editing the two ARIA goldens to drop exactly the four Recent lines is the minimal, deterministic change; CI re-verifies on Linux.

### Why not keep the panels' close X buttons?

T3 carries no panel-internal close for the details card or the right panel; closing is one toggle away. Greeneek kept a header X in Thread Details and a header bar + close in the right panel — exactly the "duplicate actions / second close path" class the owner flagged. The header toggle is the one close path; the keyboard bindings (`mod+shift+b`, `mod+j`, `mod+alt+b`) unchanged.

### Why not put Live Fleet first?

The owner's instruction is explicit and observed in the reference: Lineage first, Live Fleet directly underneath it. Previous agents is part of the Lineage hierarchy (it is the related-sessions data), so it keeps its place inside that section rather than between Lineage and Live Fleet.

### Why not merge the Dashboard "Recent sessions" table away?

It is a paginated, filterable metrics table (turns, steps, tokens, route, price coverage). The hero's five-row shortcut was a duplicate affordance of session-open; the Dashboard table is the data surface. Removing the hero seat does not touch it.

### 3. The similar feature — `@greeneek/gnk-search-query` plus sidebar integration

New zero-dependency package `packages/util/search-query` (`gnk-search-query`): Obsidian-style grammar — bare words and `"quoted phrases"` conjoin as content leaves (FTS5 `AND`), `or` disjoins (case-insensitive), `-` negates (infix FTS5 `NOT`), parentheses group, `content:` / `path:` / `file:` / `title:` operators, fail-loud `SearchQueryError`. Two truthful legs:

- **Host leg**: `session-query-sqlite` compiles content leaves into one FTS5 expression (`compileContentFts5`, pinned against runtime SQLite 3.54.0: `AND`, `OR`, parens, left-assoc infix `NOT`; unary `NOT`/`AND NOT` rejected by both the documented grammar and this build). Pure-exclusion or path/title-only queries compile to `null` — no match-all-except exists in FTS5 — and both `searchSessions` and `searchEvents` return an empty page instantly instead of a full scan. Malformed input fails loud with `SESSION_QUERY_INVALID_QUERY`.
- **Visible leg**: `tree.ts` gates the merged row set with `evaluateSearchQuery` (`enforce` for local rows — visible haystack of title/path/label/snippet; `host-authoritative` for Host-returned rows — positive content legs pass on the host's word, exclusions veto only when a visible field confirms the needle).
- **Sidebar UX**: syntax hint line under the empty search box (`search.hint`, zh/en/ar), a persisted recent-queries row of up to five chips (`gnk.search-query.recent-queries`, the `recent-searches` mirror), and the unavailable copy split into `search.syntax` (parse errors; host round-trip suppressed) vs. host failures (`search.unavailable`).
- **Selection semantics**: plain words conjoin (Obsidian semantics — juxtaposition is AND, exact phrases need `"quotes"`); `or` is the disjunction (any case; the retired behavior quoted the whole query inertly); `-` excludes everywhere visible; `path:` full working directory; `file:` basename; `title:` session title; content matches stay host-authoritative for remote rows and visible-match for local rows.

**Documented non-goals** (package README): regex (`/foo/`); `line:` / `block:` / `section:` / `task:` / `tag:` / properties (no index column; FTS5 cannot express them); `title:`-only and `path:`-only content restriction at the host (returns no content rows by design; visible legs answer); nested negation as FTS operands inside `or` units; explain-mode UI; a sort dropdown; a case-matching toggle; a global-hotkey search overlay; regex `/explainSearch/` mode.
