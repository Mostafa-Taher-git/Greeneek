# Agent Note: PTC legacy route — retiring the shipped ptc preset without unopenable history

Status: proposed


## Problem

The `presentAs('both')` opt-in toggle is shipped and CI-verified end to end: the turn-1 lock and logged vocabulary (`ad3ab29c`, run 40428750505), the `@Remote('presentCodeTools')` host trigger with silent resume re-declare (`fddab5c3`, run 40435501613), and the client chip (`a3d6a16c`, run 40440823003). The [capability-delta map](../../proposed/feature/2026-10-25-ptc-capability-delta-map.md) is the accepted contract for M1's remaining half, and the ledger reduces it to one sentence: "the migration half needs a legacy route before `presets/ptc/` can disappear" (`2026-10-25-v0.3.4-to-v0.3.6-release-ledger.md:53`, this session's row). This note is that legacy-route design. It changes no behavior itself.

The blocker the delta map fixed in source is an asymmetry, and this session re-verified each leg first-hand. A NEW session whose settings still say `default: 'ptc'` survives the preset's deletion without any new code: `defaultId` feeds the unnamed path of `resolve()`, and the roster-absent fallback composes `standard` with a warning and a `agent-preset/default-sanitized` event (`packages/preset/agent-presets/src/index.ts:389-399`). An EXISTING PTC session does not survive: resume and adopt both read the session's recorded `agentPreset` projection and pass it explicitly (`packages/api/session-controller/src/agent.ts:443` and `:478`, readings through `presetForObservation` at `:538-543`), and the explicit id of `resolve()` is never substituted — it returns the roster entry or throws `agent-preset/not-found` (`packages/preset/agent-presets/src/index.ts:388-405`; the retired-id sanitize at `:407-434` fires only when `ptc` is still resolvable AND the request is unnamed). Cold-transcript readers take the same explicit path (`standingKeyFor` → `resolveMountable` → `resolve`, `packages/api/session-controller/src/skill-catalog.ts:94-101` per the delta map's citation). Deleting the directory therefore converts every recorded-PTC session into a session that does not open.

The in-repo dependents of the directory, sorted by what they actually consume, are all verified this session:

- `apps/web/tests/ptc-round.e2e.ts:33` resolves the shipped preset with `agentPresets: { roots: [], default: 'ptc' }` (the shipped root prepends itself regardless of `roots`, `packages/preset/agent-presets/src/index.ts:197-201`) and replays `snapshots/web/ptc-round`. The delta map's survival table already classifies this fixture as preset-directory-dependent — the rest of the `ptc-*` snapshot corpus rides the host row (`tools.mode: 'ptc'` / `GNK_TOOLS_MODE`, e.g. `apps/web/tests/smoke-real.e2e.ts:634`, `apps/web/tests/scaffold.ts:294`) and survives deletion.
- `apps/web/tests/shipped-composition.e2e.ts:199` mounts `ptc` explicitly and `:198-205` pins a composition the HOST ROW CANNOT REPRODUCE: the SDK lacking `workflow:` while keeping `ralph:` is the preset's own row set (`tool-workflow` disabled at `packages/preset/agent-presets/presets/ptc/agent.cordis.yml:233-237`), not the presentation mode's. A host-row repoint composes Standard's rows under mode `ptc` and would carry `workflow:` — this panel documents the preset, not the mode.
- `apps/cli/tests/web-agent-presets.e2e.ts:226,957,961` pin the roster listing and system trust for `ptc`; `:363` mounts it explicitly; `:928-929` reads its composition file from disk.
- `apps/cli/tests/windows-shell.spec.ts:107` reads each of `standard`, `ptc`, `cordis` from the shipped root to pin platform gates.
- `packages/preset/agent-presets/tests/shipped-root.spec.ts` pins the roster (:96), the sanitize scenario (:108-117), explicit resolution (:122-130), and shipped composition probes (:211,:224-+) — but its sanitize and explicit-resolve tests STAGE their own user roots (`:145-148` writes a `ptc` directory into a temp root), so they survive deletion and keep guarding the user-trust copy (`:410`).

Two decisions only the owner can make gate the whole design:

1. **The census (UNVERIFIED in-repo).** Do any recorded-PTC sessions exist in real `GNK_HOME` stores outside this repository? Nothing in the tree can answer it (the delta map says the same at `:72`). The pre-release stance permits a hard break, but only this fact can make the break lossless rather than the picker change the decision ruled out.
2. **The continuity principle for a recorded session whose preset disappears.** Converting a corrupt-on-open into openable-but-different is also on offer below as "sanitizing the explicit path," and this note recommends against it on the "model-visible requires reconstructable" principle: silently composing an agent the session's turns never recorded is a history rewrite with no event.

## Proposal

The legacy route is not a new mechanism beamed into `resolve()`; it is the census decision plus one of two bounded work-lists. Run the census first; the answer selects the branch and is recorded in the ledger either way.

**Branch A — the census returns no recorded-PTC sessions (recommended default for this release).** Delete `packages/preset/agent-presets/presets/ptc/` (the `preset.yml` name/description and the `agent.cordis.yml` composition, the only PTC preset artifacts) and retire what only exists to serve it, keeping the generic protections:

- `RETIRED_DEFAULT_PRESET_ID` and its unnamed-path sanitize branch stay (`index.ts:74,:407-434`): a deployment that ported `ptc` into its own system-trusted root still gets the default-sanitization the v0.3.4 pill decision shipped. Only the capability of the constant's roster to match shrinks.
- The client seat keeps `HIDDEN_FROM_ROW` containing `ptc` (`packages/client/ui-agent-preset/src/client/AgentPresetSeat.tsx:89`): after deletion a user may author a `ptc` copy, and the row must keep refusing to append it; `MODE_ORDER` (:69) already omits it.
- Display copy: the `ptc` entry of `BUILT_IN_PRESET_KEYS` exits (`packages/preset/agent-presets/src/display.ts:45-65`) together with its zh/en/ar labels and the `display.spec.ts:23` row.
- Fixture repoints, verbatim from the survival table: the `snapshots/web/ptc-round` fixture and `ptc-round.e2e.ts` re-record against `toolsMode: 'ptc'` on the scaffold's host row (`apps/web/tests/scaffold.ts:294`) — the observed presentation surface is identical because the mode drives the same `tools:ptc-only`/collapse/SDK sections — this is a re-recording, and its regenerated sidecars land in the same commit. The shipped-SDK panel that pins the preset's row set (:198-205) is deleted WITH the preset, its knowledge already owned by the delta map's capability rows; the `web-agent-presets` explicit-mount coverage (:363) repoints to another shipped id, the roster pins (:226,:957,:961) drop `ptc`, and `windows-shell.spec` (:107) drops its row.
- `shipped-root.spec.ts` loses only the shipped-roster and shipped-composition assertions involving `ptc` (:96,:211,:224+); the staged-user-root sanitize and explicit-resolve tests stay untouched.
- Bookkeeping: the ledger M1 row flips to DONE-VERIFIED with this commit's run ID; the delta map's risk-136 consolidation is discharged by the implemented Agent Note for the migration (the pill note's "Everything else about PTC is deliberately untouched" line gets superseded in that note, not rewritten in place); the vault M1 row's Remaining cell empties. No byte measurement is owed: presentation behavior is unchanged, and the measurement the opt-in required was already recorded (+33,133 bytes) at landing.

**Branch B — the census returns recorded sessions.** The zero-loss route keeps every recorded session open by keeping the preset resolvable while removing it from selection surfaces, and the mechanism already has a home instead of needing an alias concept: `preset.yml` is the per-preset metadata doc that today carries `name`/`description`/`order` (`packages/preset/agent-presets/presets/standard/preset.yml:1-3`, read by `scanRoot` through `readPresetMetadata`, `packages/preset/agent-presets/src/discovery.ts:292-311`). Add an optional `retired: true` field; `scanRoot` surfaces it on `AgentPreset`; `list()` keeps returning the row (resolution, mounting, and every recorded session unaffected) while the two selection consumers filter it — the new-session row via `HIDDEN_FROM_ROW`'s row-enum logic and the Settings management listing. The seam cost is honest: one optional metadata field, `AgentPreset` gaining one field on the typed remote face (descriptor regen), two consumer filters, and their pins. The directory stays shipped until a later release's census returns empty and Branch A executes with the same work-list above.

**What this note deliberately does not propose** is noted in the alternatives section; the summary is that the "legacy route" the ledger asks for is the census discipline itself: nothing disappears until recorded sessions are accounted for, and nothing disappears silently once they are.

## Alternatives considered

**Extend the existing sanitize to the explicit path** (a named absent id resolves to `standard` with a warning and an event on resume). Rejected on the continuity principle: it converts `agent-preset/not-found` into a silently different composition — the resumed session renders runs through an agent whose roster was never in its recorded history, with no per-session event to reconstruct the change. The failure the delta map called "an unopenable history" is loud, honest, and cheap to survive (re-stage the two files from git history into a user root); this alternative is quiet and unfalsifiable from the transcript.

**Scope the explicit-path sanitize to the literal id `ptc` only.** Still rejected: the id is exactly what a user copy could reuse, and the delta map's direct source refutation stands — `resolve()`'s explicit path refusing substitution is deliberate (`index.ts:407-410` handles the explicit-and-retired and user-trust cases on the unnamed path only).

**Add a generalized rename/alias map** (`presets/ptc/` renamed, all explicit paths consult aliases). Rejected by the delta map for M1 and rejected here: an alias must be honored by `resolve`, `standingKeyFor`, `compositionInventory`, and the authoring operations; Branch A achieves the same outcome with zero new surfaces.

**Move the PTC preset's rows into `standard/`** — rejected, unchanged from the delta map (`:105`): resume opens the recorded-id gate and `standard` swallowing the rows clobbers Standard's own composition.

**Keep the shipped preset exactly as is** (the delta map's status-quo row, `:67`). It remains legal forever, but it leaves the ledger's Remaining cell open indefinitely and keeps a full second shipped composition mounted for deployments whose default has been sanitized away from `ptc` for two releases. Branch B with `retired: true` is the same zero-loss property with the selection surface actually closed, which is what the migration half asked for; if the owner prefers the status quo for v0.3.6 scope, the ledger records the owner decision and the M1 row stays honest-PARTIAL with this note as the pending design.

## Acceptance criteria

- BEFORE any migration commit, the ledger carries the owner's census answer (a stored-preset audit of real `GNK_HOME` deployments, or an explicit owner decision to hard-break), and the chosen branch is also recorded there.
- Branch A landing touches exactly: `presets/ptc/` deletion, `shipped-root.spec.ts` roster/composition pins, `display.ts` + its labels + `display.spec.ts`, the `HIDDEN_FROM_ROW` comment (entry kept, reason updated), `windows-shell.spec.ts`, the `web-agent-presets` and `ptc-round` fixture surfaces, the re-recorded `snapshots/web/ptc-round` sidecars, the ledger, both prior note consolidations, and the vault row — nothing outside that list without its own note.
- The package lane (agent-presets, 195 tests at 100% statements/branches/functions/lines per the sanitize landing) stays at full coverage with the reworked pins; no catalog regen is expected (the landing moves preset data rows, one client display map, and one metadata field at most — run `gen-cordis-catalog` at the gate as usual and let its own diff decide), `doc-sync` 30/30, `verify-client-ui-i18n`, `verify-agent-note-format`, and `verify-agent-note-classification` all pass on landing.
- `pnpm run demo:ptc` and the whole `test:snapshot` corpus except the re-recorded one keep their recorded behavior without any preset-directory dependency (survival table); the re-recorded fixture's sidecars are committed artifacts of the landing commit.
- A recorded-PTC session's open, replay, and cold-transcript read are each covered by a test against the branch's chosen posture: Branch A asserts the census premise (no session exists to test in-repo, so the suite pins the loud failure path and the recovery footing); Branch B asserts open-and-replay unchanged.
- Branch B (if chosen) ships `retired: true` on the metadata face with the two consumer filters and their tests, and BOTH filter updates ride the same commit.

## Risks

**The census is self-reported and time-sensitive.** A deployment audited today can stage a `ptc` copy or receives a fixture tomorrow; a recorded session after the audit corrupts on open. The loud failure plus the documented recovery (re-stage both files from git history as a user root, or a system-trusted port which the RETIRED sanitize keeps protecting on the unnamed path) is the bounded blast radius, and it is why the explicit-path sanitize stays rejected even here.

**Fixture re-recording churns committed goldens.** The `snapshots/web/ptc-round` sidecars and their UI expectations regenerate; the change is bounded to that fixture and pinned in the same commit, but reviewers must not read the sidecar diff as a behavior change — the note to review it against is this one.

**Branch B is a roster-API evolution.** `AgentPreset` gains a field through the typed remote face; descriptor and typed-event regen discipline applies, and `compositionInventory`/authoring paths that lean on the roster must be swept for field addition rather than behavior change.

**The consolidation writes over a shipped decision's wording.** The pill note stays authoritative for what shipped in v0.3.4; the migration's implemented note supersedes its "Everything else about PTC is deliberately untouched" sentence per the delta map's risk 136, and the ledger's M1 pill row is annotated, never rewritten.

**`presets/ptc/agent.cordis.yml` carries non-mode composition choices.** The ralph 64-round config and the disabled `tool-workflow` row die with the directory; any future need re-reads this note and the delta map's capability rows rather than resurrecting the preset wholesale.
